## 三种智能指针对比

| 特性 | shared_ptr | weak_ptr | unique_ptr |
|------|------------|----------|------------|
| **所有权** | 共享所有权 | 无所有权 | 独占所有权 |
| **引用计数** | 是（强引用） | 是（弱引用） | 否 |
| **拷贝** | ✅ 可以拷贝 | ✅ 可以拷贝 | ❌ 禁止拷贝 |
| **赋值** | ✅ 可以赋值 | ✅ 可以赋值 | ❌ 禁止赋值 |
| **用途** | 多个指针共享对象 | 观察对象，不阻止销毁 | 唯一拥有对象 |
| **循环引用** | 可能导致 | 用于打破循环 | 不会导致 |

## shared_ptr - 共享所有权

### 基本用法

```cpp
#include "smart_ptr_mt.h"
using namespace smart_ptr;

// 1. 创建
shared_ptr<int> sp1(new int(42));

// 2. 拷贝 - 引用计数增加
shared_ptr<int> sp2 = sp1;  // 引用计数 = 2

// 3. 检查引用计数
printf("use_count: %d\n", sp1.use_count());  // 输出: 2

// 4. 检查是否唯一
if (sp1.unique()) {
    // 只有我一个拥有者
}

// 5. 重置
sp1.reset();  // 引用计数减1，sp1变为空
// sp2 仍然有效

// 6. 获取原始指针
int* raw = sp1.get();
```

### 关键方法

| 方法 | 说明 |
|------|------|
| `use_count()` | 返回当前引用计数 |
| `unique()` | 返回 true 如果引用计数为 1 |
| `reset()` | 释放所有权，引用计数减 1 |
| `reset(p)` | 释放原对象，指向新对象 p |
| `get()` | 返回原始指针（不修改引用计数） |
| `swap(other)` | 交换两个 shared_ptr 的内容 |

### make_shared 工厂函数（推荐）

```cpp
// 推荐方式 - 更高效，少一次内存分配
shared_ptr<TestObject> sp = make_shared<TestObject>(100);

// 对比：直接 new 需要两次分配（对象 + 引用计数块）
shared_ptr<TestObject> sp(new TestObject(100));
```

### 跨类型转换与销毁语义

`shared_ptr<Base> sp(new Derived())` 上转构造，以及 `static_pointer_cast`、
`dynamic_pointer_cast`、`const_pointer_cast`、`reinterpret_pointer_cast` 四个转换
函数，都与源指针共享同一个引用计数块，构成一个所有权组。

销毁行为与 `std::shared_ptr` 一致：**deleter 在对象构造时就被类型擦除并保存在
引用计数块中**（保存原始指针和按原始类型销毁的函数指针），无论组内哪个引用
（基类视角还是派生类视角）最后释放，对象都按**最初构造的类型**销毁。因此：

- 基类**不需要**虚析构函数，销毁行为与引用的析构顺序无关；
- `reinterpret_pointer_cast` 的结果同样按原始指针和原始 deleter 销毁。

```cpp
struct Base { int v; };                 // 无虚析构函数，安全
struct Derived : Base { ~Derived(); };

shared_ptr<Derived> d(new Derived());
shared_ptr<Base> b = static_pointer_cast<Base>(d);
d.reset();
// b 最后析构时仍执行 delete (Derived*)原始指针，~Derived 必然执行
```

代价：每个引用计数块额外存储一个指针和一个函数指针（x86 8 字节 / x64 16 字节）。

## weak_ptr - 弱引用

### 为什么需要 weak_ptr？

`weak_ptr` 用于**观察**对象，但不阻止对象被销毁。主要用于：
1. **打破循环引用**
2. **缓存场景** - 需要时尝试获取，对象已销毁也能安全处理

### 基本用法

```cpp
shared_ptr<int> sp(new int(100));
weak_ptr<int> wp = sp;  // wp 观察 sp 指向的对象

// wp 不增加引用计数
printf("sp.use_count(): %d\n", sp.use_count());  // 仍然是 1

// 检查对象是否还存在
if (!wp.expired()) {
    // 尝试获取 shared_ptr
    shared_ptr<int> sp2 = wp.lock();
    if (sp2) {
        // 成功获取，可以安全使用
        printf("value: %d\n", *sp2);
    }
}

// 当 sp 被销毁后
sp.reset();
if (wp.expired()) {
    printf("对象已销毁\n");
}

// lock() 返回空 shared_ptr
shared_ptr<int> sp3 = wp.lock();
if (!sp3) {
    printf("无法获取，对象已销毁\n");
}
```

### 关键方法

| 方法 | 说明 |
|------|------|
| `expired()` | 检查对象是否已被销毁 |
| `lock()` | 尝试获取 shared_ptr，失败返回空 |
| `use_count()` | 返回强引用计数（观察用） |
| `owner_before()` | 用于有序容器比较 |

### 循环引用问题

```cpp
// 错误示例 - 循环引用导致内存泄漏
struct Node {
    shared_ptr<Node> next;  // ❌ 循环引用
};

// 正确做法 - 使用 weak_ptr 打破循环
struct Node {
    shared_ptr<Node> next;      // 指向子节点（强引用）
    weak_ptr<Node> parent;      // 指向父节点（弱引用）✅
};
```

## unique_ptr - 独占所有权

### 基本用法

```cpp
// 1. 创建
unique_ptr<int> up(new int(42));

// 2. 禁止拷贝和赋值
// unique_ptr<int> up2 = up;  // ❌ 编译错误！

// 3. 可以移动所有权
unique_ptr<int> up2;
up2.reset(up.release());  // ✅ up 释放所有权，up2 获得

// 4. 重置
up.reset(new int(100));  // 销毁原对象，指向新对象
up.reset();              // 销毁对象，变为空

// 5. release - 释放所有权但不销毁对象
int* raw = up.release();  // up 变为空，需要手动 delete raw
delete raw;  // 必须手动释放！
```

### 关键方法

| 方法 | 说明 |
|------|------|
| `release()` | 释放所有权，返回原始指针（不销毁对象） |
| `reset()` | 销毁当前对象 |
| `reset(p)` | 销毁当前对象，接管新指针 p |
| `swap(other)` | 交换两个 unique_ptr |
| `unique()` | 始终返回 true（独占所有权） |

### make_unique 工厂函数（推荐）

```cpp
unique_ptr<TestObject> up = make_unique<TestObject>(100);
```

## shared_array - 数组支持

### 基本用法

```cpp
// 创建数组
shared_array<int> arr(new int[5]);

// 访问元素
for (int i = 0; i < 5; i++) {
    arr[i] = i * 10;
}

// 拷贝共享所有权
shared_array<int> arr2 = arr;  // 引用计数增加

// 修改会互相影响
arr2[0] = 999;
printf("arr[0] = %d\n", arr[0]);  // 输出: 999
```

### 与 shared_ptr 的区别

| 特性 | shared_ptr<T> | shared_array<T> |
|------|---------------|-----------------|
| 构造 | `new T` | `new T[]` |
| 析构 | `delete` | `delete[]` |
| 访问 | `*ptr` / `ptr->` | `ptr[i]` |
| 拷贝 | ✅ 共享所有权 | ✅ 共享所有权 |

## 如何选择

### 决策流程

```
开始
  │
  ├─ 需要数组？ ──→ 使用 shared_array
  │
  ├─ 需要多个指针共享对象？ ──→ 使用 shared_ptr
  │
  ├─ 需要观察但不拥有？ ──→ 使用 weak_ptr
  │
  └─ 只有一个拥有者？ ──→ 使用 unique_ptr
```

### 具体场景

| 场景 | 推荐类型 | 原因 |
|------|----------|------|
| 工厂函数返回对象 | `shared_ptr` / `unique_ptr` | 明确所有权转移 |
| 函数参数（读取） | `const shared_ptr<T>&` | 避免拷贝，不改变所有权 |
| 类成员（拥有） | `shared_ptr` / `unique_ptr` | 表达所有权关系 |
| 类成员（引用） | `weak_ptr` | 避免循环引用 |
| 容器存储 | `shared_ptr` | 共享所有权，自动生命周期管理 |
| PIMPL 惯用法 | `unique_ptr` | 独占实现细节 |
| 缓存 | `weak_ptr` | 不阻止对象被销毁 |

## 常见陷阱

### 陷阱 1：从原始指针创建多个 shared_ptr

```cpp
int* raw = new int(42);
shared_ptr<int> sp1(raw);
shared_ptr<int> sp2(raw);  // ❌ 错误！两个独立的引用计数
// 会导致双重释放崩溃

// ✅ 正确做法
shared_ptr<int> sp1(new int(42));
shared_ptr<int> sp2 = sp1;  // 共享引用计数
```

### 陷阱 2：循环引用

```cpp
struct A {
    shared_ptr<B> b;  // ❌ 循环引用
};
struct B {
    shared_ptr<A> a;  // ❌ 循环引用
};

// ✅ 正确做法
struct A {
    shared_ptr<B> b;
};
struct B {
    weak_ptr<A> a;  // 使用 weak_ptr 打破循环
};
```

### 陷阱 3：使用 release() 后忘记手动 delete

```cpp
unique_ptr<int> up(new int(42));
int* raw = up.release();
// ❌ 忘记 delete raw，内存泄漏！

// ✅ 正确做法
int* raw = up.release();
// ... 使用 raw ...
delete raw;  // 必须手动释放
```

### 陷阱 4：lock() 后不检查返回值

```cpp
weak_ptr<int> wp = ...;
shared_ptr<int> sp = wp.lock();
*sp = 42;  // ❌ 危险！如果 wp 已过期，sp 为空

// ✅ 正确做法
if (shared_ptr<int> sp = wp.lock()) {
    *sp = 42;  // 安全使用
}
```
