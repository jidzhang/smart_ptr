## 二、发现的问题

### 问题 1：指针转换函数导致双重释放 [严重]

**位置**：smart_ptr.h:553-578、smart_ptr_mt.h:665-690

**原因**：`static_pointer_cast`、`dynamic_pointer_cast`、`const_pointer_cast`、`reinterpret_pointer_cast` 从裸指针重新构造 `shared_ptr`，创建了独立的 `ref_count`。原始 `shared_ptr` 和转换后的 `shared_ptr` 各有自己的引用计数，指向同一个对象。任意一个引用计数归零时 delete 对象，另一个析构时再次 delete → double-free。

**原有测试未发现此问题**：`test_static_pointer_cast` 只检查了 `sp2.get() == sp.get()`，没有验证 `use_count()`。函数返回 1 后析构函数在后台静默触发 double-free。

### 问题 2：smart_ptr.h acquire() 对 expired weak_ptr 拷贝失败 [重要]

**位置**：smart_ptr.h:248-264（acquire 函数）

**原因**：`acquire()` 的条件 `rhs.m_counter->get_ref_count()` 检查强引用计数。当 weak_ptr 已 expired（强引用为 0）但仍持有有效 counter 时，拷贝该 weak_ptr 不会递增弱引用计数，结果是得到一个空 weak_ptr 而非另一个 expired weak_ptr。

**影响**：拷贝 expired weak_ptr 后，原 weak_ptr 与拷贝的 weak_ptr 不再共享 counter，`==` 比较会得到错误结果。

**注**：smart_ptr_mt.h 无此问题，其 acquire() 已将 strong/weak 路径分开。

### 问题 3：base_ptr 构造函数异常时可能泄漏托管对象 [中等]

**位置**：smart_ptr.h:116-126、smart_ptr_mt.h:225-235

**原因**：构造函数初始化列表直接设置 `m_ptr(p)`，然后 `new ref_count`。如果 `new` 抛出 `std::bad_alloc`，`m_ptr` 指向的对象永远不会被释放。虽然 `new` 8 字节几乎不会失败，但异常安全性要求应该处理。

### 问题 4：MSVC C++11 检测门槛不一致 [低]

**位置**：test_comprehensive.cpp:190、test_comprehensive_mt.cpp:582

**原因**：库代码用 `_MSC_VER >= 1900`（VS2015+）检测 C++11，测试代码用 `_MSC_VER >= 1800`（VS2013）。在 VS2013 上，测试会编译移动语义相关代码，但库不提供移动构造函数，`std::move()` 走拷贝构造，导致 `sp1.get() != 0` 的检查失败。

### 问题 5：test_weak_ptr_reset 注释错误 [低]

**位置**：test_comprehensive_mt.cpp:256-278

**原因**：注释说 "reset() doesn't properly clear the weak_ptr"，实际 reset() 工作正常。测试没有验证 reset 后的状态就直接返回 1。

### 问题 6：smart_ptr.h release() 存在 GCC -O2 use-after-free 警告 [低]

**位置**：smart_ptr.h:267-294

**原因**：`release()` 中 delete counter 后，后续代码（通过内联展开的其他析构函数）可能访问同一块内存。这是 GCC -O2 激进内联分析的误报（MT 版因原子操作做编译器屏障所以不会触发），但应该消除。

## 三、修复内容

### 3.1 指针转换函数 [两个头文件]

**修复方式**：共享 ref_count 而非创建新的。

修改前：
```cpp
shared_ptr<T, mem_mgr> static_pointer_cast(const shared_ptr<Q, mem_mgr>& sp)
{
    return shared_ptr<T, mem_mgr>(static_cast<T*>(sp.get()));  // 创建新的 ref_count
}
```

修改后：
```cpp
shared_ptr<T, mem_mgr> static_pointer_cast(const shared_ptr<Q, mem_mgr>& sp)
{
    shared_ptr<T, mem_mgr> result;
    result.m_counter = sp.m_counter;        // 共享现有 ref_count
    result.m_ptr = static_cast<T*>(sp.get());
    if (result.m_counter)
    {
        result.m_counter->inc_ref();        // 递增共享引用计数
    }
    return result;
}
```

`dynamic_pointer_cast` 在 cast 失败时返回空 shared_ptr；成功时与 `static_pointer_cast` 相同模式。`const_pointer_cast`、`reinterpret_pointer_cast` 同理。

### 3.2 acquire() 分离 strong/weak 路径 [仅 smart_ptr.h]

修改前：
```cpp
void acquire(const base_ptr<Q, b, mem_mgr2>& rhs)
{
    if (rhs.m_counter && rhs.m_counter->get_ref_count())  // weak 路径也检查强引用
    {
        m_counter = rhs.m_counter;
        if (is_strong)  m_counter->inc_ref();
        else            m_counter->inc_weak_ref();
        m_ptr = static_cast<T*>(rhs.m_ptr);
    }
}
```

修改后：
```cpp
void acquire(const base_ptr<Q, b, mem_mgr2>& rhs)
{
    if (rhs.m_counter)
    {
        if (is_strong)
        {
            // strong: 只有对象还活着才 acquire
            if (rhs.m_counter->get_ref_count())
            {
                m_counter = rhs.m_counter;
                m_counter->inc_ref();
                m_ptr = static_cast<T*>(rhs.m_ptr);
            }
        }
        else
        {
            // weak: 只要 counter 存在就 acquire，不检查强引用计数
            m_counter = rhs.m_counter;
            m_counter->inc_weak_ref();
            m_ptr = static_cast<T*>(rhs.m_ptr);
        }
    }
}
```

这与 smart_ptr_mt.h 的 acquire() 结构对齐，单线程版本不再检查强引用计数。

### 3.3 base_ptr 构造函数 m_ptr 赋值顺序 [两个头文件]

修改前：
```cpp
explicit base_ptr(T* p = 0) : m_counter(0), m_ptr(p)  // m_ptr 在初始化列表赋值
{
    if (m_ptr)
    {
        if (is_strong)
            m_counter = new ref_count;  // 如果抛异常，m_ptr 已赋值，对象泄漏
    }
}
```

修改后：
```cpp
explicit base_ptr(T* p = 0) : m_counter(0), m_ptr(0)  // m_ptr 初始为 0
{
    if (p)
    {
        if (is_strong)
            m_counter = new ref_count;  // 如果抛异常，m_ptr 仍为 0
        m_ptr = p;                      // new 成功后才赋值
    }
}
```

### 3.4 release() use-after-free 修复 [仅 smart_ptr.h]

采用与 smart_ptr_mt.h 相同的模式：用局部变量保存 counter，提前清零 m_counter。

```cpp
void release(void)
{
    if (m_counter)
    {
        ref_count* counter = m_counter;
        m_counter = 0;  // 提前清零

        if (is_strong)
        {
            if (0 == counter->dec_ref())
                mem_mgr::deallocate(m_ptr);
        }
        else
        {
            counter->dec_weak_ref();
        }
        if (0 == counter->get_ref_count() && 0 == counter->get_weak_ref_count())
            delete counter;
    }
    m_ptr = 0;
}
```
